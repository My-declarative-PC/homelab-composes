# Beszel Agent

Compose-проект запускает только агент Beszel и Docker socket proxy. Общая конфигурация находится в `compose.yaml`, а отличия конкретной машины — в отдельных файлах `hosts/`.

## Настройка

1. В интерфейсе Beszel на mini-сервере добавьте систему и выберите WebSocket-подключение. Скопируйте выданные для агента `KEY` и `TOKEN`.
2. В корне репозитория создайте локальный `.env` из шаблона и заполните значения для этой машины:

   ```sh
   cp -n available/beszel-agent/template.env available/beszel-agent/.env
   ```

   `.env` игнорируется Git. Команда не перезаписывает уже существующий файл. Для ноутбука оставьте `COMPOSE_FILE=compose.yaml`. Для рабочей станции установите `COMPOSE_FILE=compose.yaml:hosts/workstation.yaml` и `SYSTEM_NAME=workstation`; при ручном добавлении системы укажите это же имя в интерфейсе Beszel. Используйте отдельный `TOKEN` для каждой системы. `CONTAINER_NAME` уникален в пределах одного Docker-хоста и задаёт имя каталога данных агента, поэтому не меняйте его при уже сохранённых данных.

3. На workstation создайте каталог-маркер для отдельной файловой системы `/home`:

   ```sh
   sudo mkdir -p /home/.beszel
   ```

4. На нужной машине включите и запустите проект:

   ```sh
   hctl enable beszel-agent
   hctl up beszel-agent
   ```

Конфигурация workstation собирает SMART для HDD Seagate и SSD ADATA, использует зашифрованную Btrfs `cr_root` для корневого раздела и отдельно отслеживает `/home` на `cr_home`. Остальные Btrfs-сабвольюмы не перечисляются: они используют пространство корневой файловой системы.

Агент использует исходящее WebSocket-соединение к хабу, а SSH-сервер агента отключён. Docker socket proxy предоставляет агенту доступ только к чтению данных о контейнерах и логов; его порт опубликован только на `127.0.0.1` и доступен агенту через host network.
